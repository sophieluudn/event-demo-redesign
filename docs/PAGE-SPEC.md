# 頁面與流程規格

## 頁面總覽

| Demo | 用途 | 主要內容與操作 |
|---|---|---|
| `index.html` | 活動首頁 | 活動資訊、簡介、地點、籌辦單位、聯絡資訊、報名、查詢 |
| `register.html` | 報名入口 | udn 會員報名、一般報名 |
| `form.html` | 報名表單 | 個資、飲食、個資同意、送出 |
| `payment.html` | 付款項目 | 選擇場次／商品、前往付款 |
| `success.html` | 報名成功 | 報名資訊、付款資訊、電子憑證、列印 |
| `query.html` | 報名查詢 | 手機號碼、發送 OTP、驗證 |
| `query-result.html` | 查詢結果 | 多筆紀錄、狀態、付款、電子憑證 |

正式路由可依既有系統調整，不要求沿用 `.html` 路徑。

## 主要流程

### 報名

`活動首頁 → 報名入口 → 報名表單 → 審核／付款 → 報名成功`

- 會員登入、資料帶入、審核及付款條件沿用既有網站。
- Demo 的跳頁與「等待審核中」彈窗只表達介面情境。

### 查詢

`活動首頁 → 報名狀態查詢 → 手機驗證 → 查詢結果`

- 手機完成基本格式檢查後，才可要求既有系統發送 OTP。
- OTP 驗證成功後才能取得報名紀錄。
- 個資遮罩、嘗試次數及鎖定規則沿用既有系統。

## 各頁規格

### 活動首頁

- 導覽錨點：活動資訊、活動簡介、活動地點、籌辦單位、聯絡資訊。
- 活動資訊包含活動期間、場地、地址、報名期間與名額。
- 支援加入 Google 行事曆；外部連結需安全地另開頁籤。
- 籌辦單位支援 Logo 卡片及純公司名稱文字名單。
- 聯絡資訊的電話與 Email 均為不可點擊的純文字。
- 小於 1024px 顯示收合導覽；1024px 以上顯示完整導覽，錨點維持單行、間距 24px。

### 報名入口

- 提供 udn 會員報名及一般報名。
- 會員入口串接方式沿用既有網站；返回首頁為次要操作。

### 報名表單

| 欄位 | 必填 | Demo 型態 | 備註 |
|---|---:|---|---|
| 姓名 | 是 | text | 正式限制沿用既有系統 |
| 電話 | 是 | tel input | 顯示時仍為純文字；格式規則沿用既有系統 |
| 電子信箱 | 是 | email input | 需呈現格式錯誤 |
| 服務單位／職稱 | 否 | text | 正式資料結構依既有系統 |
| 飲食習慣 | 否 | select | Demo：葷食、素食、清真飲食 |
| 個資同意 | 是 | checkbox | 未勾選不可送出 |

- 個資聲明可捲動並可由鍵盤取得焦點。
- 送出需有 loading、disabled、防重複送出及錯誤回饋。

### 付款項目

- 顯示活動名稱、可選項目及金額，同時只能選一項。
- Demo 金額與場次是假資料，正式內容由既有系統提供。
- 付款中需防重複點擊，並依既有機制處理離站、回跳及失敗。

### 報名成功

- 報名資訊：序號、活動名稱、時間、場地、地址。
- 付款資訊：商品、訂單編號、金額、狀態、交易序號與時間。
- 不適用付款資訊時可隱藏整個區塊。
- QR Code 必須來自正式憑證；Demo SVG 不可直接沿用。
- 電子憑證可在 Modal 檢視及列印。

### 報名查詢

- 手機：Demo 規則為 `09` 開頭 10 碼數字。
- OTP：Demo 規則為 6 碼數字。
- 手機通過前端檢查後才顯示 OTP 區塊。
- 正式版需有發送中、已發送、倒數、重送、錯誤與次數限制。

### 查詢結果

- 支援同一查詢回傳多筆紀錄。
- 顯示姓名、電話、Email、報名序號及狀態。
- 個資遮罩沿用既有系統；電話與 Email 均不可點擊。
- 提供再次查詢及返回首頁。

## 狀態與操作

| 狀態概念 | Demo 文案 | 操作 |
|---|---|---|
| completed | 完成報名 | 查看 QR Code |
| reviewing | 審核中 | 無 |
| awaiting_payment | 等待付款 | 前往付款 |
| rejected | 審核未過 | 無 |

正式狀態碼及轉換完全沿用既有系統。前端建立狀態 mapping，不以中文文案判斷。

## 正式版須補齊的狀態

- 頁面／區塊 loading、查無資料、一般錯誤、逾時。
- 欄位驗證、登入失效、重複送出。
- OTP 失敗、過期、重送、達次數限制。
- 付款取消、失敗、待確認及重複回跳。
- QR Code 無效或尚未產生。
