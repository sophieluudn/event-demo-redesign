# 互動與狀態規格

## 共通原則

- 本文件描述 UI 結果；商業規則以既有系統為準。
- 每個非同步操作至少有 idle、loading、success、error。
- loading 期間避免重複送出；錯誤後允許合理重試。
- 電話與 Email 顯示一律是純文字，不產生 `tel:` 或 `mailto:`。

## 導覽與語系

- 目前章節以藍色文字、24px 寬短底線及 `aria-current="location"` 標示，字重維持 400；桌面與收合選單同步，點擊及捲動時更新。

- 桌機顯示章節連結、語系、報名查詢、立即報名。
- 小於 1024px 時，選單按鈕展開／收合導覽，`aria-expanded` 與畫面同步。
- 選擇收合選單連結後自動收合；錨點定位避開 sticky header。
- 視窗切到 1024px 以上時重設選單為關閉，縮回窄視窗後維持關閉。
- Demo 只展示繁中與 EN，正式語系 URL、內容與 fallback 沿用既有系統。
- 當前語系不可只用顏色標示。

## 表單驗證

- 必填欄位具可見 label 與必填標記。
- 操作或嘗試送出後才顯示錯誤，避免初始載入全部報錯。
- 錯誤訊息與欄位程式化關聯，且可被螢幕閱讀器讀出。
- 送出失敗後聚焦第一個錯誤欄位或錯誤摘要。
- 前端驗證只改善體驗，正式資料仍由後端驗證。

## 報名表單送出

1. 檢查必填、格式及個資同意。
2. 不通過時保留輸入，顯示錯誤並聚焦第一個錯誤。
3. 通過後按鈕 loading 並防止重複送出。
4. 依既有回應顯示等待審核、付款、完成或錯誤。
5. 失敗時解除 loading，安全地保留內容並提供重試。

Demo 的「等待審核中」彈窗只是視覺示意，不可用固定 timeout 或假狀態取代正式回應。

## OTP 查詢

- Demo 手機格式為 `09` 開頭 10 碼；不符時不得發送並聚焦欄位。
- idle：發送驗證碼。
- loading：按鈕 disabled，顯示發送中。
- sent：顯示 OTP 區，聚焦 OTP，提供已發送提示。
- cooldown：顯示倒數，結束才可重送。
- error：顯示原因及可行下一步。
- rate-limited／locked：清楚說明限制，不只 disabled。
- OTP 為 6 碼並支援 `autocomplete="one-time-code"`。
- 錯誤、過期與達次數限制分別回饋；成功後才可查詢資料。

## 付款

- 點擊整列及鍵盤皆可選取，狀態有視覺及程式化表達。
- 付款按鈕執行後 loading 並禁止重複提交。
- 離站、回跳、取消、失敗及待確認沿用既有整合。
- 不可只依 query string 或前端狀態認定成功。

## 查詢結果

- 顯示筆數與卡片數一致。
- 狀態碼透過 mapping 決定標籤與操作。
- 完成報名可開憑證；等待付款可付款；其他狀態不顯示不適用操作。
- 查無資料顯示空狀態與重新查詢。

## Modal 與電子憑證

- 開啟後焦點進入 Modal，背景不可操作。
- 支援關閉按鈕與 Esc；關閉後焦點回到觸發按鈕。
- 標題具程式化關聯；內容超高時內部可捲動。
- QR Code 附文字識別資訊，不可只提供無說明圖片。

## 列印

- 只輸出憑證，不輸出導覽、Footer、遮罩、關閉與列印按鈕。
- 報名序號及 QR Code 不可裁切，並以實際紙張／PDF 驗證可掃描性。

## 外部內容

- 外部連結另開時使用 `noopener noreferrer`。
- Map iframe 具 title，並依既有隱私政策決定載入方式。
- 資訊圖片具替代文字；純裝飾圖片使用空 alt。
